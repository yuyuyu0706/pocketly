## 8. Phase 6 – 成功指標の測定（Milestone 6）

### 8-1. 成功指標一覧（Charter §7 より）

| # | 指標 | 判定方法 |
| --- | --- | --- |
| 1 | A4 換算 10 ページ相当の Markdown が HTML エクスポート・PDF 出力ともに全ページ印刷できる | 実測（印刷プレビューのページ数） |
| 2 | 主要な装飾操作がキーボードのみで完結する | 対象操作リストに対する Yes/No |
| 3 | ネットワーク遮断状態でアプリが起動しプレビューが描画される | 実測（オフライン再現） |
| 4 | 表を含む文書の作成が、Excel からのコピペを起点に完結する | シナリオ実演 |
| 5 | Playwright テストが主要機能の回帰を検出できる | 対象機能リストとテスト件数 |
| 6 | 閲覧モード（既定）の常時表示操作要素が **5 個以内** であること | 実数カウント |
| 7 | 利用者が設定する項目の増加数が **0**（または合意した上限以内） | 実数カウント |

### 8-2. 指標 6 の測定方法（確定）

**測定対象**: 閲覧モード（既定起動時）に常時表示されている最上位の操作要素数

**測定手順**:

1. `npm run dev --workspace=markdown-editor` でアプリを起動する
2. ブラウザで `http://127.0.0.1:8000/` を開き、編集モードへの切り替え操作を一切行わない状態にする
3. 画面上に常時表示されている操作要素（ボタン・アイコン・トグル等）のうち、「折りたたみ状態でも最上位レベルで見えているもの」を目視でカウントする
   - 折りたたみ・ドロップダウンの内側に収納された項目は対象外
   - ツールチップは対象外（操作要素ではないため）
4. カウント数が 5 以下であれば合格

**常時チェックのタイミング**: Phase 3〜5 の各 Lv2 PR で閲覧モード UI を変更した際は、PR 内で実数カウントを確認し記録する（早期発見のため）

### 8-3. 指標 7 の測定方法（確定）

**測定対象**: Phase 1 開始時点を基準とした設定項目数の増加数

**基準値**: Phase 1 開始時点で利用者が設定できる項目は 0 件（専用の設定 UI が存在しない）

**測定手順**:

1. Phase 5 完了後に、利用者が設定できる項目（設定パネル・オプション画面・ローカルストレージへの永続設定等）の総数を数える
2. 基準値（0）との差分を算出する
3. 差分が 0 であれば合格。差分がある場合は、各 Lv2 PR での合意記録（「設定項目の追加を合意した」旨の記録）と照合し、合意済みの追加のみであれば合格

**常時チェックのタイミング**: Phase 3〜5 の各 Lv2 PR で設定項目を追加する場合は、PR 内で理由と合意を明記する

## 10. 運用ルール（再発防止）

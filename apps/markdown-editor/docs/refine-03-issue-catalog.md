## 1. 判定基準（Charter §6 より再掲）

```text
優先度-高 = a) 現在すでに壊れている
           b) コンセプト実現の必須要素かつ規模 M 以下
           c) 安全性・可用性に関わる

優先度-中 = 体験を明確に向上させるが、現状でも代替手段がある
優先度-小 = あると嬉しいが、無くてもコンセプトは成立する
対象外   = 将来構想として記録し、本 Refine では実装しない

土台性-高 = 2 件以上の他課題の前提、または後回しで作り直しが発生
           → 優先度に関わらず Phase 2 へ配属
```

規模: S = 1 日以内 / M = 数日 / L = 1 週間超

#### MDE-023 テキスト編集処理が 12 箇所に重複し undo を壊す

| 項目 | 内容 |
| --- | --- |
| 分類 | 基盤 |
| 事象 | 本文を書き換える処理が 12 箇所に個別実装されており、いずれも `editor.value` 直接代入のためブラウザの undo スタックを破棄する |
| 原因 | `script.js:434` / `545` / `992` / `1194` / `1249` / `1313` / `1428` / `1806` / `2365` / `2419`、`js/preview.js:477` / `481` |
| 影響 | `MDE-004` の直接原因。また同じ「値の差し替え → ハイライト更新 → AppState 反映 → 行番号更新 → フォーカス復帰」の定型処理が全箇所にコピーされており、装飾を 1 つ追加するたびに定型を再実装する必要がある |
| 規模 | M |
| 土台性 | **高** — `MDE-004` / `005` / `015` / `019` / `020` の前提 |
| 方針案 | 共通ユーティリティ `replaceEditorRange(start, end, text)` を新設。内部で `setSelectionRange()` → `document.execCommand('insertText', ...)` を使い、`input` イベント経由の変更にすることでネイティブ undo に載せる。非対応環境は現行の直接代入へフォールバック |
| 備考 | `execCommand` は deprecated だが、textarea の undo 連携を保つ実用手段は現状これのみ。将来的な `EditContext` API への移行余地をコメントで残すこと |

#### MDE-001 HTML エクスポート結果が 1 ページしか印刷できない

| 項目 | 内容 |
| --- | --- |
| 分類 | 不具合 |
| 事象 | エクスポートした HTML を印刷すると 1 ページ目で切れる |
| 原因 | `script.js:2527-2615` が `style.css` 全文を `<style>` へ埋め込むため、`style.css:1-6` の `body { height: 100vh }` と `style.css:329-335` の `#preview { height: 100%; overflow: auto }` が適用される。高さ固定 + `overflow:auto` のボックスはブラウザが改ページ分割できない |
| 影響 | 資料を配布する全ケース。「Markdown で資料を作る」の最大の障壁 |
| 規模 | M |
| 土台性 | 中 |
| 依存 | `MDE-024` → `MDE-025` |
| 方針案 | エクスポートには `document.css` のみを使い、アプリシェル CSS を流出させない。`@page { size: A4; margin: … }`、`html, body { height: auto; overflow: visible }`、`pre, table, figure, .mermaid { break-inside: avoid }`、`h1, h2, h3 { break-after: avoid }`、`thead { display: table-header-group }` を含める |
| 備考 | `EXPORT_STYLESHEET_FALLBACK`（`script.js:2453-2525`）には `height: 100vh` が無く、`file://` でフォールバックした場合のみ印刷が通る。**症状が環境で異なる原因はこれ。** 再現確認は HTTP 経由（`npm run dev`）で行うこと |

#### MDE-003 3 ペイン常時表示が窮屈

| 項目 | 内容 |
| --- | --- |
| 分類 | 体験改善 |
| 事象 | 目次・エディタ・プレビューが 1 ウィンドウに常時並び、それぞれが狭い |

| 備考 | Charter §3-2 で主用途 C が確定。本課題はゲート条件 b)（コンセプト実現の中核）に該当し、規模 L のまま優先度-高で確定（Issue #51）。サイドバー型グローバルナビ構想は `refine-04-vision.md` D-8 にも記録済み |

# pocketly 開発ルール（Claude Code 向け）

このファイルは、Claude Code がこのリポジトリで作業する際に毎セッション読み込む項目です。
本ファイルには、常時参照すべき原則のみを置きます。アプリ固有の詳細な規約・手順は
`apps/<app>/docs/conventions/`等へ切り出し、本ファイルからは参照のみを記載します。
行数ではなく「アプリ固有の詳細が紛れ込んでいないか」を分割要否の判断基準とします。

## ブランチ作成前に必ず最新 main を取り込む

クラウドセッションの環境はファイルシステムのスナップショットを再利用するため、
「新規セッション」であっても内部のリポジトリ状態が古い main を指している場合があります。
作業ブランチを作成する前に、必ず以下を実行してください。

```bash
git fetch origin
git checkout main
git pull origin main
git checkout -b <ブランチ名>
```

これを省略すると、他の Issue が先にマージした変更を取り込まないまま作業ブランチを
作成してしまう場合があります。マージ自体は3-way mergeで通常安全に解決されますが、
セッション内で行う `npm run validate:feature-docs` などのローカル検証が、
最新化されていない古い内容に対して行われることになり、確認の精度が下がります。

## 複数ウィンドウ・PiP対応時の規約

DOM要素が別ウィンドウ（PiP・ポップアウト等）に移動しうる処理を書く場合、
`document`/`window`を静的固定参照せず、`element.ownerDocument`／
`element.ownerDocument.defaultView`経由で動的解決すること。詳細・正例・
例外基準は `apps/markdown-editor2/docs/conventions/window-and-multi-window.md`
を参照。

## issue 作成時のルール

Issue作成時は、下記に基づいて作成してください。

- Issue テンプレート
  - Lv1：`.github/ISSUE_TEMPLATE/lv1_issue.md`
  - Lv2：`.github/ISSUE_TEMPLATE/lv2_issue.md`
  - Lv3：`.github/ISSUE_TEMPLATE/lv3_issue.md`
  - Lv4：`.github/ISSUE_TEMPLATE/lv4_issue.md`

- 制約
  - 対象 issueの作成以外の更新操作は不要です。
  - まだ実装には着手不要です。
  - issue作成後、issue番号とURLを報告して停止してください。

## PR 作成時のルール

PR作成時は、下記に基づいて作成してください。

- 制約・指示
  - 実装対象Issue の範囲のみを実装すること。
  - PRは「claudecode/」から始まるブランチ名で作成すること。
  - 実装完了後、PR作成まで進めて良い。
  - PR本文の内容は、50行以内とすること。
  - PR本文でIssueを自動クローズするキーワード（Close #、Closes #、Fixes #、Fix #、Resolves #、Resolve #）は使用しない
  - Issue との関連付けは「Issue #NNN の実装」のような非クローズ表記に統一すること。
  - PR作成後、PR番号とURLを報告して停止すること。
  - Github上の更新操作は、作業ブランチのpush、PR作成のみ。issueの更新操作は不要。

## レビュー時のルール

レビュー時は、下記に基づいてレビュー実施および報告してください。

- 指示・制約
  - GitHub上の更新・コメント・マージなどの変更操作は行わないでください。
  - 開発状況は、基本事項に記載のブランチURLの内容を確認してください。
    - GitHub UI（blob表示）ベースで確認してください。
    - 行番号ベースで確認したいです。
    - 必要に応じて、PRの Files changed を基準に、現在の差分を確認してください
  - 問題点が見つかった場合は、修正依頼文を作成してください。
    - Markdown形式で30行以内で作成してください。
    - 問題点が、1~3件なら30行以内、4~5件なら50行以内で文章作成してください。
    - 問題点が、6件以上なら相談を挙げてください。
    - ダウンロード可能な形式で提供してください。
  - 下記の確認結果テンプレートに基づいてチャットしてください。
    - 最終検証結果一覧
      - 1行目に、mainマージは OK (マージGO) か、NG (マージ保留) を1行太字で記述してください
      - 2行目に、指摘・問題点の件数有無を1行で記述してください。
      - 3行目以降に、検証結果一覧表を記述してください
    - 指摘事項一覧
      - 一覧表で列挙してください。
        - 一覧表の列は、問題名、重要度、必須度の3点としてください。
        - 詳細解説は修正依頼文を見る為、チャットでは不要です。
    - 総評
      - 3行以内の総評と、問題点があった場合は修正依頼文のダウンロードリンクを配置してください。
